# Qiskit Fall Fest 2026 Website — Agent Rules

## Project Goal

Build a professional, responsive, public-facing event website for
Qiskit Fall Fest 2026.

## Official Source Priority

The uploaded Qiskit Fall Fest 2026 Kickoff PDF is the primary
source for official event requirements and branding rules.

The Brazil Qiskit Fall Fest reference PDF is a secondary source
for event-organization inspiration only.

Do not treat the Brazil PDF as the source of official 2026 branding,
deadlines, event facts, or claims.

## Accuracy Rules

Never invent:
- event dates
- venue
- speakers
- speaker affiliations
- registration URLs
- organizer names
- IBM/Qiskit partnerships
- statistics
- official claims

Anything not confirmed must be marked TBD or "Coming soon".

## Branding Rules

Never modify official IBM/Qiskit/Qiskit Fall Fest assets.

Never:
- recolor logos
- stretch logos
- distort logos
- add effects to logos
- redraw logos
- combine official logos into unofficial marks

Creative freedom is allowed for:
- page layout
- backgrounds
- cards
- typography
- buttons
- spacing
- animations
- custom illustrations
- section design

Do not imply the event is an official IBM-hosted event
unless explicitly confirmed by the event staff.

## UX Rules

The website must be:
- premium
- modern
- professional
- accessible
- mobile-first
- fast
- easy to scan
- suitable for public external visitors

Avoid:
- excessive gradients
- excessive neon
- generic AI landing-page aesthetics
- unnecessary animations
- clutter
- huge paragraphs
- fake statistics
- fake testimonials

## Technical Rules

Use:
- Next.js
- TypeScript
- Tailwind CSS
- reusable components
- semantic HTML
- accessible keyboard navigation
- responsive layouts
- optimized images
- metadata/SEO
- clean component architecture

## Development Rules

Do not make large destructive changes without explaining them.

Before implementing a major feature:
1. inspect the existing project
2. explain the intended approach
3. implement
4. run validation
5. inspect the result
6. fix issues

## Verification

After each major UI milestone:
- run the app
- inspect it in the browser
- test desktop and mobile
- check console errors
- check broken links
- check accessibility
- check overflow
- check CTA behavior

## Content

Use clean, concise event copy.
Do not overclaim.
Do not use placeholder content in production.
